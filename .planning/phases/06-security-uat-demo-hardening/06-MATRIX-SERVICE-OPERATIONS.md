## Hypotheses (planning time)

- **(a) Pickup queue visible across hubs**: confirmed. `ShipmentServiceImpl.createShipment` sets only `destinationHubId`; `originHubId` stays null for HOME_PICKUP until `FirstMileServiceImpl.assignPickup` binds it. `ShipmentRepository.findPendingPickups` selects `(s.originHubId is null or s.originHubId = :hubId)`, and `pendingPickups()` returns sender name, phone and address. A coordinator of any hub therefore sees every unclaimed home pickup nationwide and can claim it for their hub. Workflow §16/§29 do not define per-hub pickup visibility and Phase 02 D-07 kept the slice minimal, so by the rubric's documented-requirement test this is **MEDIUM with an owner decision required** (F-06-H-01). Suggested fix if the owner restricts it: derive `originHubId` at creation from the sender's province (the same lookup the destination uses), then drop the `is null` branch.
- **(b) `createHandover` checks only the receiver's role**: confirmed. An inactive driver or a driver profile with the wrong position can be named, but `LinehaulTripServiceImpl.requireActiveDriver` blocks acceptance, so the handover cannot progress → F-06-H-02 (LOW).
- **(c) Any HUB_STAFF position at the current hub reads the audit timeline**: confirmed; out-of-scope reads are masked as not found → F-06-H-03 (LOW, policy).
- **(d) `completePickup` hub-null compatibility branch**: discarded. `lockOwnTask` always compares `shipper.getHubId()` with `shipment.getOriginHubId()` before the branch, so hub scope cannot be weakened; the branch only chooses which `markPickedUp` overload records the hub.
- **(e) `ReturnDisposalController` injects the concrete service**: discarded. `disposalCandidates` and `disposeOverdueReturn` call `managerScope()` / `requireManagerScope()` inside the service, so no controller path bypasses the scope (PTS#disposalCandidatesAreForManagersAndAdministratorsOnly, ShipmentReturnServiceImplTest#crossHubHeldAndOutboundCannotDispose).
